# skyward-common v1.5.1 — Consumer Migration Checklist

This release contains a **breaking change to the LLM provider interface**, a cost-accuracy fix, an additive competitor data model, and the DataForSEO standard-mode work. Every repo that imports `skyward.llm` must read **Section 1** before bumping. Sections 2–4 are additive/optional.

**Affected repos (known LLM consumers):** `skyward-seo-pipeline-kagg` (categorize + `llm_log`), AI-Content-Workflow / FAQs, WQA GA4 loader, `reddit-monitor`, and anything else calling `provider.call(...)`.

---

## 1. LLM provider — `provider.call()` now returns `LLMResult` (BREAKING)

### What changed
`provider.call(...)` (all 5 providers: OpenAI, Gemini, Perplexity, Anthropic, Grok) **no longer returns a `(content, input_tokens, output_tokens)` tuple.** It returns a single `LLMResult` dataclass. `call_text()` / `call_structured()` return `LLMResult` too.

```python
@dataclass
class LLMResult:
    content: Any                  # parsed model (if response_model) OR full text
    input_tokens: int
    output_tokens: int
    cache_read_tokens: int = 0
    cache_write_tokens: int = 0
    latency_ms: int | None = None
    model: str | None = None
    stop_reason: str | None = None
    raw_text: str | None = None        # provider text pre-parse
    reasoning_text: str | None = None  # gpt-5*/o1*/Gemini-thinking/Claude-thinking; else None
    raw: Any = None                    # untouched SDK response
```

### Required code changes
Find every call site that unpacks the 3-tuple and update it:

```python
# BEFORE
result, in_tok, out_tok = provider.call(messages, model, response_model=Foo)

# AFTER
r = provider.call(messages, model, response_model=Foo)
result  = r.content
in_tok  = r.input_tokens
out_tok = r.output_tokens
```

- [ ] Grep each repo for `.call(`, `.call_text(`, `.call_structured(` and any tuple-unpack of the result.
- [ ] Replace tuple unpacking with `.content` / `.input_tokens` / `.output_tokens`.
- [ ] **`LLMSession.send()` is UNCHANGED** — it still returns the content (string or parsed model), not an `LLMResult`. Session token totals (`session.total_input_tokens` / `total_output_tokens`) still work.

### New capabilities you can now use (optional)
- [ ] `r.cache_read_tokens` / `r.cache_write_tokens` — prompt-cache usage (see Section 2 for cost).
- [ ] `r.latency_ms` — per-call latency.
- [ ] `r.raw_text` — provider text before parsing (useful for `llm_log` audit).
- [ ] `r.reasoning_text` — reasoning/thinking summary for reasoning models (OpenAI gpt-5*/o1* require requesting a summary, e.g. `reasoning={"summary": "auto"}`; Anthropic populates it when extended thinking is enabled; `None` otherwise).
- [ ] `r.stop_reason`, `r.model`, `r.raw`.

### kagg `llm_log` specific
- [ ] Wire the placeholder columns to the new fields: `output_raw_text ← r.raw_text`, `reasoning_text ← r.reasoning_text`, and store `cache_read_tokens` / `cache_write_tokens` / `latency_ms`.
- [ ] Update the categorize stage's tuple-unpack (Section 1) and the pre-run estimate.

## 2. `calculate_cost()` — corrected rates + cache-aware (action: re-baseline cost numbers)

### What changed
- **gpt-5 family rates were wrong** (gpt-5-mini billed at gpt-4o-mini rates → ~3× undercount). Now correct: gpt-5 `1.25/10`, gpt-5-mini `0.25/2.00`, gpt-5-nano `0.05/0.40`. Verified vs live OpenAI pricing (Jun 2026).
- **Date-suffixed model ids are matched to the family** (`gpt-5-mini-2025-08-07` → `gpt-5-mini`).
- **Cache-aware:** new optional kwargs `cache_read_tokens=` / `cache_write_tokens=`. Per-model cached rates (gpt-5 fam = 10% of input, gpt-4o fam = 50%, Anthropic read = 10%, 5m write = 1.25×). For OpenAI/Gemini, `input_tokens` is assumed to **include** cached tokens (cache reads are subtracted before billing); for Anthropic they are separate.
- **Anthropic cost table refreshed** to current models (`claude-opus-4-8`, `claude-sonnet-4-6`, `claude-haiku-4-5-20251001`); retired keys kept for historical rows.

### Required / recommended
- [ ] **Expect cost numbers to change.** Any consumer reporting "actual cost" for gpt-5* will now report the correct (higher) value. Re-baseline dashboards/budgets/alerts.
- [ ] Pass cache tokens for accurate cost: `calculate_cost(r.input_tokens, r.output_tokens, model, provider, cache_read_tokens=r.cache_read_tokens, cache_write_tokens=r.cache_write_tokens)`.
- [ ] Signature is backward-compatible (new args default to 0) — existing positional calls keep working, just more accurate.
- [ ] (Optional) historical `llm_log.cost_usd` rows under-bill gpt-5*; backfill if you need accurate history.
- [ ] ⚠️ **Gemini cost table was NOT updated** this release (tiered pricing) — treat Gemini cost as approximate until a follow-up.

- [ ] Gemini: `gemini-2.0-flash` → use `gemini-2.5-flash` (or current).

## 4. Site-scoped competitors (ADDITIVE — non-breaking; migrate when ready)

No code breaks here. New `meta.site_competitors` table + MetaClient/DataHub helpers model competitors **per site** (directional). The legacy `client_domains.is_competitor` flag is **untouched and still authoritative** until you migrate consumers.

- Prod is already backfilled (client-level competitors fanned out to each client's brand sites; multi-site fan-outs are a "safe superset" pending manual trim).
- New helpers: `get_site_competitors`, `add_site_competitor`, `add_site_competitors`, `add_site_competitor_by_domain`, `get_sites_competing_with`, `remove_site_competitor`, `set_site_competitor_priority`, `set_site_competitors`, `copy_site_competitors`, `get_client_competitors`, `set_client_domain_competitor`.
- [ ] (Later) KAGG competitor resolution (`shared.competitors.domain_ids`, `load_competitors`) → read from `site_competitors` / `get_client_competitors`.
- [ ] (Later) `seo_pipeline` `_lookup_client_id` → unchanged (still uses ownership = `is_competitor=false`).
